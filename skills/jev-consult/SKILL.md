# Jev consult

You inspect this repo and write code. **Jev decides.** Default: call Jev. Skip only facts a tool can check, and mechanical follow-through of a pick Jev already made this session.

Jev is TypeSafe System One. Answers are only Choice, Noul, or Score. Jev has no memory: every call needs current `state`. Jev cannot see files, skills, plugins, MCP, or a marketplace. Jev cannot write "go this way" in prose. A redirect is the chosen option.

## Limits (read this)

Jev does **not** maximally eliminate hallucinations. A 0% invalid-type rate is not a 0% wrong answer. Do not ask Jev "is this Wikipedia fact true" with empty evidence — that is another guess. Cut invented *decisions* by forcing a Choice among options you inspected. Check facts with tools. If evidence is in `state`, you may Noul `grounded_enough` before proceeding.

There is **no watchdog** in Hermes, Claude Code, Codex, or Grok. If you skip this skill, Jev is not called.

Never print `TYPESAFE_API_KEY`. Never auto-install marketplace items.

## How to call


Repo copy: `python skills/jev-consult/scripts/jev.py`. Installed user copy: `scripts/jev.py` next to this skill.

Write `request.json` from `policy.json` templates (`scaffold` copies them; add `--option ID=key:label` when criteria are empty). Put real options in `criteria`. Include a hatch (`none` / `other`) when the policy says so. Pass `state`: human plan, current step, files, attempt count, last error, shortlist.

Read `decision.action`. `proceed` → take `answers`. `escalate` → stop and ask the human. If `ask` stdout has no `decision.action`, do not pick architecture, library, or approach. Scaffold then ask.

Thresholds live only in `policy.json`.

## Jev owns

`approach`, `keep_vs_change`, `architecture`, `library`, `delete`, `refactor_vs_rewrite`, `naming`, `good_enough`, `on_track`, `stuck_move`, `unknown_move`, `load_tools`, `installed_enough`, `market_tools`.

You own inspection, inventory, marketplace search (names only), code, tests, and translating the typed answer into an action.

## Off-track

If the current step is not the human plan (wrong file, extra feature, different stack):

1. Put `plan` and `current_step` in `state`.
2. Noul `on_track`.
3. If no / unsure: Choice `next_move` (`return_to_plan` / `change_approach` / `ask_human` / `none`).
4. Do that option. Do not invent a fourth path.

## Stuck

Call Jev when you repeat the same edit, hit the same error twice, make no file/test progress, or cannot solve. Jev cannot see a loop unless `state` has it:

- `attempt_count`
- `last_error`
- `what_did_not_change`

Then Choice `stuck_move` (`change_approach` / `narrower_scope` / `ask_human` / `stop` / `none`). Do not retry the same failing step after that pick.

## Don't know

When you do not know the next step (no approach, no library, no move):

1. Do not invent. Put `unknown` and what you already inspected in `state`.
2. Choice among those real options plus `ask_human` / `none`. If it is a loop, use `stuck_move` instead.
3. Do that option.

If you do not remember the plan, load `.jev-trace.json` first (`--trace`). If it is missing, `unknown` is the plan. Template: `examples/forget.request.json`.

Jev only sees this request. Labeled examples belong in this `state` or in criteria `examples` arrays — they do not accumulate between calls. Jev does not raise an LLM's intelligence; it only picks.

## Don't stall

Do not keep writing an answer when you lack a next file, command, or Jev pick. That stall is `unknown_move` (or `stuck_move` if you already looped). There is no watchdog: if you skip this skill, Jev is not called.

## Trace

Jev and a new session forget. `.jev-trace.json` is the memory you stuff into each ask.

```text

python skills/jev-consult/scripts/jev.py ask request.json --trace
python skills/jev-consult/scripts/trace.py record --pick return_to_plan --kind next_move
python skills/jev-consult/scripts/trace.py state --out state.json  # bare state dict for scaffold --state
python skills/jev-consult/scripts/trace.py notes  # list notes (--json for the array, --limit N caps rows, --prune N rewrites to last N, --edit I TEXT rewrites note I — or I-J rewrites every note in the range — (1-based, keeps ts/iso/harness, recomputes sha; rc 2 out of range), --since TS / --before TS bounds notes by ts, --harness H filters tagged notes, --grep SUBSTR filters note text (JEV_TRACE_GREP presets), --uniq dedupes by sha/text, --by-harness counts notes per harness, --shas prints each filtered note's sha (--json emits {shas}), --rate prints per-day buckets + notes_per_day, --gap S lists consecutive notes more than S seconds apart ({index,prev_ts,ts,gap_s,prev_text,text} rows; --json nests them under gaps), --out PATH writes the listing to a file, --field F prints only field F per note, --reverse lists newest-first); `trace.py history` lists recorded picks (--json, --limit N, --field F prints only field F per pick, --since/--before TS bounds by pick ts, --reverse lists newest-first, --grep SUBSTR filters pick/kind text, JEV_TRACE_HISTORY_GREP presets, --kinds prints the distinct history kinds with counts, --uniq dedupes by pick+kind (first occurrence wins; applied before --limit), --rate prints pick-rate stats `{count, stamped, first_ts, last_ts, span_s, days, picks_per_day, per_day}` over the filtered history — UTC day buckets, `--json` nests it under `rate`, `--gap S` lists consecutive-pick gaps wider than S seconds as `{index, prev_ts, ts, gap_s, prev_pick, pick}` rows — `--json` nests them under `gaps`); `trace.py set --dry-run` emits the would-be trace (`{path, trace, dry_run: true}`) without writing; `trace.py prune --dry-run` reports would_remove without deleting; `trace.py stats` (reports {exists, attempt_count, history, inspected, notes, notes_bytes, history_bytes, last_pick, has_error, has_unknown, age_seconds}) / `trace.py show --out PATH` writes its JSON to a file (`show --jq KEY` digs one dotted-path trace field, rc 2 on unknown — takes precedence over `--key`; a comma list `a,b` emits them as an object); `trace.py export` dumps the whole trace bundle (state, history, notes, counts, file) as JSON (`--out PATH` writes it to a file; `--since TS`/`--before TS` bound the exported history+notes by ts — epoch or ISO8601, rc 2 on a bad value; `trace.py diff A B` diffs two trace files key-by-key — scalars under `changed`, list items under `added`/`removed`, `only_a`/`only_b` keys, `different` flag, `a_exists`/`b_exists` (`--jq KEY` digs it, `--out PATH` writes it); `trace.py self-test` records+reads a pick on a temp trace file and exits 1 when it does not round-trip (`{self_test, history, last_pick}`); `init`/`set`/`bump`/`record`/`prune`/`self-test` take `--jq KEY` printing one dotted-path field of their emitted `{path,trace}`/`{removed,...}`/`{self_test,...}` payload (rc 2 on unknown; a comma list emits a `{field: value}` object — same on `stats`/`verify`/`diff`/`env`/`suggest`/`export` `--jq`); `trace.py schema` prints the `.jev-trace.json` key contract (`--json` emits the object); record --note appends one (stamps a 12-char `sha` of the text for dedupe; tag it with --harness H); `trace.py suggest` asks Jev for the next move — it builds a `next_move` (or `--template` other) choice question from policy.json templates plus the trace state, runs the Jev ask, and records the pick into history (`--pick X` skips Jev and records X directly, `--kind` tags the entry, `--dry-run` prints the request without calling or recording, `--ask-file`/`--out` save the request JSON, `--jq KEY` prints one field)
```

## Compact

Default is **LIVE_FAT only** via `scripts/compact_hook.py`: it truncates the current fat tool result (>32k chars) as it arrives. Hermes `transform_tool_result`, Claude and Grok `PostToolUse` `updatedToolOutput`. Errors and small reads stay. The omitted middle is saved whole to `~/.cache/jev-consult/spill/<sha>.txt` and the marker names the file (cap 200, `JEV_CONSULT_SPILL=0` disables). `--verbose` prints the skip reason to stderr when the emitted payload is `{}` (`not a PostToolUse event`, `toolResultTruncated`, `no tool result text`, `tool result is an error`, `below live-fat threshold`, or `empty stdin`/`invalid JSON`/`payload is not an object`/`unreadable --file PATH` for bad input). `--file PATH` reads the event JSON from PATH instead of stdin (fail-open `{}` when unreadable); `--simulate TEXT` runs a synthetic PostToolUse event with TEXT as the tool result — a quick probe of the live-fat decision without crafting JSON. `--env` prints the resolved hook config JSON (live_fat/live_head/live_tail, spill_dir, spill_disabled, spill_max_files/spill_max_bytes, policy source — `default` or the JEV_POLICY path; `--jq KEY` prints one value, `--out PATH` also writes it, fail-open); `--verdict PATH` writes a slim `{verdict: compacted|skip, reason}` JSON after the run (fail-open on a bad path); `--self-test` runs `handle()` on synthetic payloads (fat abridged, thin/error/wrong-event skips) and exits 1 on failure (`self-test: ok|FAIL <check>=ok|FAIL ...`). Not a watchdog. No second-LLM summary. No post-compact resync.

Do **not** run session-history drop as the default. Hermes eval (Teknium, 2026-09-20) did not adopt Tamara retention: it deletes old tool calls, breaks the prompt cache, and loses to production summary. Codex has no mutate hook — that is not a reason to rewrite dumps.

`compact.py --history` still exists as opt-in (Python port of `vendor/fast-jev-compaction`, MIT). Do not call it from hooks. `--keep-text PATTERN` pins messages/tool calls whose text, tool name, or input matches the regex — never dropped regardless of the asker; an invalid regex is ignored. `--dry-run` reports decisions+stats while returning the messages unchanged (never writes spill files; combined with `--json` it emits only `{"dry_run","stats"}` — no messages payload). `--preview` prints `{"preview", "plan": [{id, tool, action, reason}], "stats"}` — the per-call drop plan — without writing output files or spill. Other opt-ins: `--dir DIR` batch (one JSON line per file plus a `batch:` footer with ok/char totals; files are processed sequentially — each can spend a live Jev ask per compaction batch, so budget ~seconds per file), `--spill-max-files N`/`--spill-max-bytes N` override the `spill_max_files`/`spill_max_bytes` GC caps from `policy.json` for this run, `--list-spill`, `--spill-stats` (spill-dir totals `{dir,count,bytes,oldest_ts,newest_ts}`; `--json`/`--out PATH` apply), `--prune-spill S` (`--out PATH` writes the listing to a file) — the spill dir keeps an append-only `index.jsonl` of `{ts,name,bytes}` rows per write (never listed or pruned itself; `--list-spill` reports indexed bytes/ts, stat-fallback for stray files), `--verify-spill FILE` checks `full output saved:` refs resolve, `--orphan-spill FILE` lists unreferenced spill files (`--json` makes the spill commands and `--dir` emit structured output (batch mode: one `{"files","count","ok","chars_in","chars_out"}` object)), `--diff A.json B.json` diffs two compact result files (`-o` output) per call id — `{calls_a, calls_b, same, changed:[{id,tool,a,b}], only_a, only_b}` (rc 1 on unreadable/non-result input, `--json`/`--jq KEY`/`--out PATH` apply), `--stats`/`--stats-json` stderr summaries, `--explain` prints one stderr line per tool-call decision (id tool action reason scores), `--report PATH` writes the stats JSON to a file, `--md` emits a markdown stats summary instead of the JSON payload (`-o` writes the markdown to the file too), `--jq KEY` prints one dotted-path field of the result JSON (e.g. `stats.calls`, rc 2 on unknown); `--min-messages N` returns the transcript untouched when it has fewer than N messages (`stats.skipped: "min_messages"`), `--self-test` compacts a synthetic transcript with a stub asker (no Jev call) and exits 1 on failure — `self-test: ok|FAIL <check>=ok|FAIL ...`, `--json` emits `{self_test, checks}`; `--schema` prints the compact result/decision/spill-index/spill-stats key contract (`--json` emits the `{key: {required, type}}` object); `--check` exits 1 when the transcript would compact below the `--min-reduction` gate (prints `check: ok|FAIL reduction ...` only; `--json` emits `{"check","reduction","min_reduction","rc"}`), `--keep-first N` to pin the first N messages; `--watch S` re-reads the transcript file and re-runs compaction every S seconds emitting a `{"ts","messagesBefore","messagesAfter","charsBefore","charsAfter","reduction","fallback","elapsed_s"}` tick per pass (`JEV_COMPACT_WATCH_MAX` caps ticks; each pass also prints a `watch tick=N reduction=.. fallback=..` stderr summary; a capped watch exits 1 when the last pass fell back to the original; `--fail-fast` stops after the first pass that falls back; `--out PATH` appends each tick line, fail-open; `--verdict PATH` writes a slim `{verdict: ok|fallback, ticks, reduction, fallback}` JSON, refreshed every tick (or a one-shot `ticks: 1` probe without `--watch`)).

## Session tools

Native harness tools are already in the session. A hook IDF-shortlists **already-installed** skills / plugins / MCP, then one Jev Choice + `need_skill` (8s timeout, fail-open to the IDF list). The user does not pick tools. Hook never installs.

| Harness | What runs without the user |
| --- | --- |
| Hermes | plugin `jev-compact` `pre_llm_call` injects up to 6 names |
| Claude Code | `UserPromptSubmit` → `inventory_hook.py` additionalContext |
| Grok | `UserPromptSubmit` writes `.jev-tools.json` (stdout context is discarded) |
| Codex | `UserPromptSubmit` → `~/.codex/hooks.json` → `inventory_hook.py` additionalContext (trust in `/hooks` or Codex skips it). If skipped: miss file → `peer_fill` / `catalog_fill` / `apply_fill`; else sidecar or inventory then Jev |

Hook may call Jev **once** on the IDF shortlist (`load_tools` + `need_skill`). Timeout fail-open. Winner injects one `<skill_relevance>` line; `none` injects nothing. A repeat of the exact same prompt in a directory with a fresh `.jev-tools.json` replays that sidecar's pick without a second Jev call (`dedupe: true` in the log entry). A choice with `load_tools` probability ≥ `strong_pick` (0.85 in `policy.json`) wins even when `need_skill` is unsure. Every hook decision is appended to `~/.cache/jev-consult/decisions.jsonl` (`JEV_CONSULT_LOG=0` disables). Hook never installs. Never `--force`. Never npx.

`.jev-tools.json` and `.jev-tools-miss.json` sidecars carry `written_at`; the tools sidecar also carries `note_sha` (sha256 prefix of the emitted note) so readers can dedupe repeats. They are fresh for `sidecar_ttl_seconds` (policy.json, 4h default). Check with `python scripts/inventory.py --check-sidecar` (`fresh` / `stale` / `missing` / `invalid`, plus `age Ns` when parseable). Stale sidecar → ignore it and re-run `inventory.py`; `read_miss` already returns `{}` on stale miss files. `python scripts/inventory.py --prune-sidecars DIR` unlinks stale/invalid `.jev-tools*.json` under DIR recursively (`--dry-run` lists without deleting); `--show FILE` dumps the parsed payload plus `age_seconds` and schema checks (`valid`/`issues`). Pass `--ttl SECONDS` to override the policy TTL on any of those; the `JEV_HOOK_TTL` env var (seconds) overrides it everywhere, including the hooks. `inventory.py --roots` prints the resolved scan roots for `--harness` as JSON — `{skills,plugins,mcp_files: [{path,exists,items}]}` — handy when a harness finds nothing. `inventory.py --item NAME` prints the single scanned record verbatim as JSON (accepts `name` or `kind:name`, falls back to case-insensitive; exits 2 when absent). `inventory.py --item-all NAME` prints *every* matching record (e.g. a skill and an mcp server sharing a name) as a JSON array — same matching rules, exits 2 when none. `inventory.py --dupes` lists names that appear more than once — across harnesses when `--harness` is auto, within the selected harness when it is set — as `{count, dupes: [{name, count, harnesses, kinds}]}` (`--out PATH` writes it to a file instead of stdout; `--baseline-write PATH` snapshots the list for later `--baseline PATH` runs that drop the recorded dupe names — baseline applies only with `--dupes`). `inventory.py --schema` prints the scan payload + shortlist item key contract (`--json` emits the object). `inventory.py --env` prints the resolved config JSON (task/limit/log source, JEV_INV_WATCH_* knobs, policy; `--jq KEY` prints one field, rc 2 on unknown).

The hook enforces a wall-clock budget: `hook_budget_seconds` (policy.json, 12s default) caps each invocation; on timeout it skips the Jev pick, logs `jev_status=budget`, and returns the IDF shortlist without a winner (fail-open). A Jev call that times out is logged as `jev_status=timeout` (distinct from generic `error`), also fail-open.

`jev_status` vocabulary (the value logged to decisions.jsonl and echoed by `--verbose`/`--debug`): `winner` (one pick chosen), `none` (Jev declined to pick), `escalate` (decision wants a human), `dedupe` (fresh sidecar replayed a repeat prompt), `idf` (no Jev pick — shortlist only), `empty` (shortlist was empty), `skip` (no API key), `timeout`, `budget`, `error`, `fill` (written by the peer/catalog/apply fill scripts, not the hook). Each hook-logged entry also carries `reason`, a one-line human explanation of how the status was set (e.g. forced pick via `JEV_HOOK_WINNER`, explicit `$name` mention, dedupe carry-over, budget hit).

## Opt-in contribution review

`progress.py` is a stateful CLI, not a daemon or a mechanism that remotely controls a Devin session. Enable it only for an explicitly agreed stage. The caller must read its `action` and honor review, repair and budget-exhaustion states. Routing hooks remain unchanged and fail-open.

Review and commit a stage plan before `init`: goal, fixed work-item IDs, literal repository-relative paths for each item, trusted verification commands, required checks, operating system and any preauthorized next directions. Commands in a plan execute locally without a shell; never initialize an untrusted plan. `{python}` selects the current Python interpreter. The example plan requires Windows and must be adapted to the actual agreed outcomes.

The initial rubric is zero/small/material/major = 0/1/2/3, with a review checkpoint of 12 credits. These are starting heuristics, not measured accuracy or percentages of completion. Settings and prompts come only from `policy.json` and are frozen in each stage. A custom scale requires matching rubric categories and point mappings before initializing a new stage.

Assess a clean committed tree after completing an agreed item. Commands run against that tree; the captured baseline, scoped diff, check exit codes and output hashes ground the Jev request. Passing a command alone does not prove the goal was met. Raw diffs and command output are not retained in the ledger. Unknown, uncertain, unavailable or oversized evidence is unscored, not zero. No silent truncation is used.

One item earns positive credit once. Repeated item/tree requests are cached even if the commit ID or summary changes; an identical previously credited patch earns no new credit under another item. `--retry-unavailable` retries only an unavailable request, never a low grade or uncertain answer. Assessment of a credited item on a changed tree and stage review detect a full return of its scoped source to the baseline and revoke that credit. Explicitly invalidate other disproven or partially regressed outcomes; this is not a background regression detector. A reviewed, freshly verified restoration restores only the original credit and requires a current scoped change relative to the baseline.

A checkpoint triggers review, not completion. Review reruns checks and asks Jev to continue, finish or choose a direction authorized in the frozen plan. `--approve-finish` is an explicit caller acknowledgement, not authenticated human identity or proof of independent review. Use it only after actual acceptance review; passing checks and an unblocked Jev decision are still required. Finishing below the checkpoint is allowed. A pivot closes the stage without claiming completion. Continue reviews never reset the assessment or request-attempt budgets.

The SQLite ledger is local, under `.devin/progress.sqlite3` by default. Keep it out of Git, protect its directory with appropriate OS permissions and retain it separately if a cloud VM will be discarded. History and hashes support audit and reproducibility; they are not tamper-proof attestations against an actor with filesystem access. Request-attempt limits are workflow safeguards, not a cloud billing quota or a guarantee about a process killed during a request. No hooks, repository settings, deployments or cloud-session controls are changed automatically.

`progress.py` global flags go before the subcommand: `--repo` (git root), `--db` (ledger path), `--policy` (policy file used by `init`). `--schema` prints the init-plan key contract (`id`, `goal`, `checks`, `required_checks`, `items`, `directions`, `platform`, `item.*`) with required/optional markers — `--json` emits the `{key: {required, type}}` object. `lint PLAN` dry-validates a plan against the `--policy` file (or the pack default) with the same checks as `init`, writes nothing, and exits 1 with `{"lint": "invalid", "code", "message"}` when either is rejected. `report STAGE` prints a markdown summary (goal, action, per-item credit, event log) to stdout — `--out PATH` writes it atomically and prints `{"wrote", "bytes"}` JSON instead; `status`/`history --out PATH` do the same for their JSON payload outside `--watch`. Every subcommand takes `--jq KEY` to print just that dotted-path field of the result payload (rc 2 on an unknown key); the non-watch subcommands (`init`, `evidence`, `assess`, `invalidate`, `restore`, `review`, `self-test`) also take `--verdict PATH` writing a slim `{verdict: ok|error, command}` JSON after the run — `action`/`points`/`stage` are copied through when the result has them, and a ProgressError writes `{verdict: error, command, code}`. `self-test` initializes a scratch ledger with a stub evidence collector — no Git worktree and no Jev call — and prints `{"self_test": "ok"}`. `status STAGE --watch S` re-reads the stage every S seconds emitting a `{ts,stage,action,reason,points,review_at,assessments,model_attempts,awarded,blocked,elapsed_s}` tick per pass, and `history STAGE --watch S` emits a `{ts,stage,events,delta,last_kind,last_seq,elapsed_s}` count tick per pass (`delta` is vs the previous tick, `null` on the first), and `report STAGE --watch S` emits a `{ts,stage,chars,sha,delta,elapsed_s}` tick per pass (`sha` fingerprints the markdown; `delta` marks content changes) — both take `--max-ticks N`/`JEV_PROGRESS_WATCH_MAX`, `--watch-max S`/`JEV_PROGRESS_WATCH_SECS`, `JEV_PROGRESS_WATCH_QUIET` presets `--quiet`, `--out PATH` appends ticks, `--verdict PATH` refreshes a slim payload (`{verdict: active|resolved, ticks, action, points}` for status, `{verdict: steady|changed, ticks, events, delta}` for history, `{verdict: steady|changed, ticks, chars, delta}` for report); without `--watch` the same payload is written once with `ticks:1` (status verdict is `active`/`resolved`, history/report `steady`); status `--fail-fast` stops on the first non-`continue` tick and history's on the first count change, and the watches exit 1 when the last tick is still `continue`/errored (status) or empty (history), or errored/empty (report). Assessment events carry `status` `scored`/`unscored`: `unscored` covers unknown, uncertain, unavailable or withheld evidence and earns nothing. The ledger/evidence engine itself lives in `progress_core.py`, an import-only module shared with `policy_lint.py`; run standalone it answers only version/help and prints its usage.
